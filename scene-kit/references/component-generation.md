# 单体参考包与 AI 3D

## 先建立整栋三维参考模型

设计合同确认后，先建立一个 `reference_only` 整栋三维模型，再开始组件拆件。优先选择能同时展示主立面、入口、屋顶和侧向体量的 3/4 视图。支持多图输入时，同一对象按正面、背面、左侧、右侧提交；只有单图接口时，如实记录单图模式和由此带来的不确定性。

整栋参考模型的作用：

- 看到门窗、窗台、窗套、檐口、托架和门廊在三维中的退进、突出、遮挡和连接。
- 识别同一个构件在正面与侧面不是同一平面上的形状。
- 为组件拆件提供连续三维上下文，避免把窗台误认为墙体、把玻璃误认为只有正面一张面片。

整栋参考模型不能直接作为最终拆件母体：

- 它通常由一张视图推断不可见部分，存在形变和细节幻觉。
- 门窗、栏杆和装饰常与墙体融合，不能稳定切出干净拓扑。
- 自动材质和局部细节不能替代项目 PBR 与多视图验证。

模型必须先减面、单独保存、标记 `reference_only`，再按以下顺序完成参考验证：

1. 验证实际网格不是空文件，主体体量、屋顶、主要洞口和附着关系可辨认，写入 `reference_quality`。
2. 默认使用统一缩放，保留模型本身的轴向比例。估算占地或单图构图不能成为非均匀拉伸的依据。
3. 用同一模型中心、同一正交尺度、同一分辨率和固定方向定义建立 `camera_rig`；每个视图只改变固定视角，不重新构图。
4. 实际渲染固定十视图并检查存在性、非空、同一建筑、比例与取景，写入 `derived_view_validation`。
5. 顶视/底视通常是开放壳体模型的低可信视图。主要拆件依赖正面、背面、左右侧和四个 45 度视图；顶/底只辅助屋架、烟囱截面或底面关系。
6. 记录网格连通岛报告，在组件映射中使用 `mesh_island_ids` 追溯候选。候选岛必须先经过多视图语义校验，不能自动等同于完整组件。

组件识别首先读取这组模型派生视图并建立 `feature_extraction.component_map`。原始十视图只用于校验模型是否出现明显幻觉、缺项或比例问题，并补充可靠材质和纹理。`analysis_ready=true` 必须同时覆盖参考质量、归一化、固定相机轨道、视图验证和组件映射五项门禁。

只有 `analysis_ready=true` 后，才进入下面的组件拆件和参考包环节。

## 先盘点视图中的全部资产

不要只从用户视图中找门窗和结构件。逐张查看参考模型派生的十视图，把有独立造型价值的非结构元素列入 `visual_inventory`，再用原始图校验：

- 浮雕、木雕、徽章、线脚、铁艺花纹和雕塑归为 `decorative_ornament`。
- 花簇、草、藤蔓、灌木、树和垂植归为 `vegetation`。
- 壁灯、花盆、长椅、标牌和小喷泉归为 `site_element`。
- 门、窗、栏杆、柱和门廊归为 `architectural_component`。
- 墙段、屋面、楼板和楼梯归为 `structure`。

有轮廓、厚度、可独立安装或可重复使用的元素，应拆成独立组件。纯色、污渍、颗粒和没有几何厚度的花纹优先用 PBR 或法线贴图。无法分清单体边界的密集植物，先做成一个代表性花簇、灌木或藤蔓模块，再在 Blender 中实例化。

每个 `part` 都必须记录 `asset_class` 和具体 `type`。例如不能只写 `decoration`，要写 `stone_relief`；不能只写 `plant`，要写 `flower_cluster` 或 `climbing_vine`。

## 细节特征扫描

大构件拆件完成不代表资产盘点完成。逐张查看十视图时，至少检查以下层次：

1. **轮廓层**：烟囱、塔楼、尖顶、屋脊、老虎窗、山墙、雨棚和挑檐是否改变外轮廓。
2. **近景层**：檐口、托架、牛腿、窗套、百叶、门五金、台阶、栏杆、壁灯和山花是否有可辨认厚度。
3. **重复层**：不同窗型、门窗框变体、压顶石、转角石、栏杆段和装饰块各有多少种、多少个实例。
4. **附着层**：檐沟、落水管、排水口、烟囱帽、壁灯、花箱和其他屋面/墙面构件是否被漏掉。
5. **表现层**：浮雕、木雕、铁艺花纹、藤蔓、苔藓、瓦纹、砌石和抹灰哪些需要几何，哪些只需 PBR 或法线。

结果写入 `components.detail_audit`。`scan_views` 必须引用选中方向的全部十视图；`coverage` 的六个 `*_scanned` 都要为真。即使在某个视图中确认“不存在”，也要完成对应类别扫描，不能凭其他视图臆测。

每个特征使用类似记录：

```json
{
  "feature_id": "chimney_front_right",
  "category": "attachments_and_services",
  "type": "chimney",
  "views": [
    "concepts/D04/views/front.png",
    "concepts/D04/views/right.png",
    "concepts/D04/views/front_right_45.png"
  ],
  "quantity": 1,
  "visual_impact": "silhouette",
  "geometry_required": true,
  "disposition": "part",
  "part_id": "chimney_front_right",
  "observation": "右侧屋面烟囱在正视图形成明确轮廓，侧面可确认深度与屋面交接。"
}
```

`visual_impact=surface_only` 且 `geometry_required=false` 时可以使用 `disposition=material`。需要几何的特征不能只写材质；它必须进入 `part`、`parametric` 或 `reuse`。`disposition=part` 必须声明 `geometry_required=true` 并引用真实组件，`unresolved` 通过时必须为空。

接口示意图通常只表达包围盒、原点和连接面，不能用来判断烟囱、山花、屋脊饰和雕花是否完整。细节缺失必须在 `COMPONENTS` 修复，不能留到 `FINISHING` 临时补猜。

窗、门、栏杆和格栅还要单独写组件 `fine_structure_review`。窗格至少确认主竖向分区、中央是否再分列、总列数、总行数、横档数和总格数；用放大裁剪检查框料粗细层级，不能把“12 格”当成对所有分格窗都成立的默认值。框、窗套和玻璃的基础颜色与粗糙度也在这里先记录，随后交给材质审查验证。

### 视觉模型辅助复核

当十视图细节密集或 Agent 无法直接浏览原图时，使用 `scripts/detail_vision_audit.py`。推荐组合：

1. Florence-2 逐视图详细描述。
2. Florence-2 短语定位：`chimney / window / door / balcony / railing / plant / vine / lantern / decoration / carving / steps / roof / tower`。
3. 从正、右、左、顶视图提取代表性裁剪。
4. 对裁剪再做详细描述。
5. 用独立 ViLT VQA 检查“是否木质、是否存在、是不是烟囱/塔”等关键歧义。
6. 对窗格增加 4 倍放大裁剪，分别检查主分区、中央再分列、行列数和材质身份。
7. 把模型结果与原始十视图、线位候选和局部放大图交叉比对。

模型输出只能作为诊断证据。烟囱和塔帽外形相似时，优先保留复合名称和未解决项；不能用一次模型回答强行决定组件类型。详细安装、依赖和输出见 [detail-vision-audit.md](detail-vision-audit.md)。

## 拆件后必须回查原多视图

单视图裁剪很容易把构件裁残、把相邻墙体带进来，或让侧面和安装背面丢失，最终装配时像散件。组件先在模型派生有效视图中确定三维范围，并用 `mesh_island_ids` 记录候选来源，再回到选中方向的原始十视图中回查。至少选择两个真实原始来源，写入 `decomposition_audit.source_views`；来源必须是选中方向的 `view_paths`，不是任意局部图。

网格岛候选只是一组空间连通面，可能包含多个构件的一部分，也可能是同一构件的多个断开块。最终组件身份、数量、边界和安装方向必须由模型派生多视图与原始多视图共同确认。若候选池噪声较大，保留候选报告并把语义归属写入人工审查记录，不能为了“每个岛都有名字”而制造错误组件。

逐项检查：

- 目标构件是否完整包含正侧轮廓、顶部、底部、侧厚和必要安装面；
- 是否把墙体、门窗、相邻浮雕、环境或重复构件误并进一个部件；
- 同一轮廓、比例和构件数量在正面、侧面、背面或 45 度视图之间是否一致；
- 拆分后是否仍有连续墙体、屋面、框架或支撑关系，而不是只有孤立的装饰块；
- 拆下的多个部件是否存在重叠、缺口、双重表面或无法解释的悬空。

每个组件记录 `decomposition_audit.status`、`checks` 和 `notes`。整栋资产盘点、多视图一致性和装配连续性写入 `components.decomposition_review`。任何一项无法解释时先修拆件，不进入 AI 生成。

## 生成前的多参考共识

拆件回查与生成参考核对不是同一件事。即使已经有 `decomposition_audit`，开始参数化建模或 AI 3D 前仍必须为当前组件建立 `reference_consensus`：

1. 从至少两个不同视角裁出目标构件，保留完整外框、安装面和足够的周边关系。
2. 分别记录身份、轮廓、结构、材质和附着关系；不能共用一条泛化描述。
3. 对每个主要材质角色从多个视图采样颜色和光泽。记录方法、RGB、环境光差异和最终共识。
4. 用视觉模型描述和独立问题复核作为辅助证据，再与调色板、放大图和结构测量交叉验证。
5. 出现身份、结构、材质或安装分歧时先补裁剪或换视图；未解决时保持 `repair_required`，不生成。
6. 所有六项一致性检查通过并记录 `confirmed_before_generation=true` 后，才可进入建模或生成。

模型输出不能单独证明材质。例如各视角都描述“dark”时，仍可能是深褐木、灰褐木、黑漆或蓝灰金属；必须比较色相和相对通道。一个视角说黑、另一个说棕时，应检查白平衡、阴影和窗框高光，而不是取最高置信度。

视觉扫描多视图裁剪和调色板位于 `preview/detail-scan/multi_view_evidence.json` 与 `crops/multi_view/`，可作为候选证据；最终构件裁剪和结论仍写入 `reference_consensus`。

## 组件边界与附件

组件按实体范围划分，不按一张正视图里的色块划分。开始建模前使用 `boundary_review` 记录三维边界：

- 六个面：正、背、左、右、顶、底。
- 两个尺寸：包含全部附着结构的整体包围盒，以及与墙体/楼板接触的安装接口。
- 附件清单：窗台、窗套、披檐、盖板、压顶、托架、铰链、框料和返口。
- 材质区：同一组件内部可以同时存在木、石、玻璃和金属。

附件记录至少两个证据视图、突出量、材质和处置方式。与当前构件一起安装、随它移动的结构，应设为 `included_in_component` 并实际建出几何；真正独立安装的附件才可以设为 `separate_component` 并链接 `part_id`。不要为了得到一个简单包围盒而删除外侧窗台、檐口或托架。

窗组件必须把外突石质窗台纳入自己的边界。正面负责确认宽度和窗台位置，侧面/45 度负责确认突出量、厚度和挡水边；背面负责确认安装面。任一视角都不能单独决定组件范围。

## 三种参考资料

### geometry

中性正视图、侧视图、厚度和接口。它回答“模型怎样装进去”。

- 保留轮廓、门窗洞、边框和连接面。
- 不加最终材质、环境、人物和强烈灯光。
- 不用整栋审阅图替代单件轮廓。

### appearance

回答“这个构件看起来应该属于哪种设计”。

- 可以是选中概念图的局部裁剪。
- 可以是单独生成的单件概念图。
- 可以是第一件通过验收后的风格锚。
- 不应同时包含多个相邻构件，避免 AI 把它们连成一体。

`reference_pack.audit` 必须把裁剪结果与原始多视图对照。检查裁剪没有截断目标构件、没有带入相邻构件或隐藏环境、与多视图一致，并保留足以判断安装、侧厚和收口的边缘。图片完整指的是构件语义和安装逻辑完整，不只是分辨率够高。

### review_only

回答“整栋空间关系是否正确”。

- 整栋灰盒。
- 完整建筑审阅渲染。
- 帮助用户判断体量、比例和镜头。
- 禁止进入 AI 3D 的几何参考。

## 每个组件的自由合同

建筑组件的 `locked` 必须包含：

- 接口宽度、高度、厚度或深度。
- 原点和朝向。
- 墙面或楼板接触面。
- 门窗洞尺寸或派生规则。
- 允许误差。

浮雕、装饰件、植物和场地点景的 `locked` 至少包含：

- 最大宽度、高度、深度或代表模块的包围盒。
- 原点、正面朝向和安装方向。
- 墙面、花箱或地面接触面。
- 允许的缩放范围。
- 重复实例的数量或布置规则。

浮雕必须只取自身轮廓和安装背面，不能把整面墙一起交给 AI 3D。植物优先生成“有代表性的单株或小簇”，不要逐叶、逐花生成。

`guided` 应包含：

- 构件类型与时代语言。
- 主要轮廓和视觉重心。
- 材料倾向、色彩、线脚密度。
- 与风格锚的关系。

`free` 应包含：

- 窗格细分方式。
- 门板构图。
- 栏杆花纹和柱头。
- 雕花、嵌板、五金和局部装饰。
- 允许 AI 重新解释但不破坏接口的范围。

如果 `free` 为空，改用参数化、复用或资产库。如果 `locked` 为空，不得进入精确装配。拆件完成后先按分类、类型、标签和风格搜索模型库；有候选时让用户选择复用或重新生成。

## 参数化合同

每个组件都必须登记 `parametric_contract_id`。即使组件当前选择 AI 3D 或模型库，也要记录可控包装参数；`parametric` 决策则必须提供实际可重建的生成器。

优先参数化的组件：

- 墙体：立面尺寸、楼层带、槽位、洞口尺寸、窗台、入口限制、随机 seed。
- 窗门：接口宽高、框厚、框深、行列、分格、玻璃、窗套和窗台。
- 屋面、台阶、栏杆、线框和转角石：坡度、间距、阵列数、截面和转角规则。
- 基座和楼板：内外轮廓、厚度、高度、退让、开口。
- 植物和装饰：包络、实例、密度、朝向、seed、材质和镜像。

参数改动后不得复用旧材质图、贴图审计或组件 QA。必须重新生成并重新验收。合同结构和脚本命令见 [parametric-components.md](parametric-components.md)。

## 双语提示词

每个 AI 单体必须提供完整：

1. English positive。
2. English negative。
3. 中文正向。
4. 中文负向。
5. 参考图用途说明。

英文正向结构：

```text
One isolated <part type>, <core design description>.
<locked silhouette and interface constraints in relative terms>.
<guided design language and material cues>.
<free creative details>.
<fixed positive style paragraph>.
<fixed view paragraph>.
<repeatable component, neutral background, no building context>.
```

负面必须包含：

```text
complete building, environment, people, extra connected components,
floating fragments, labels, watermark,
<fixed negative style paragraph>
```

不要在提示词中写“高度 2.1 米”之类的绝对尺寸。绝对尺寸在导入 Blender 后按锁定接口校准。

## 生成输入选择

已经有构件参考图时，默认先提交图生 3D 或多视图生成。不要把“参考图加文字”拆成一次文生图、一次纯文字 3D；文字只随参考图一起控制接口和设计语言。

**例外（7.16）**：藤蔓、花簇、盆栽等小尺度有机构件如果只有在境裁剪参考（同框包含墙面、窗户、地面或花盆），或图生 3D 已因此串入建筑/环境，改用纯文生 3D 隔离单体，同时在 `generation.text_only_reason` 写明原因。触发信号、提示词合同和生成后处理见 [generation-routing.md](generation-routing.md) 的“小尺度有机构件的文生 3D 例外”。

整栋参考模型和组件映射完成后，才为组件选择执行方式。提交单件 AI 3D 前必须完成 `route_assessment` 并在 `reference_model_id` 引用整栋参考模型。重复规则构件优先 Blender；只有高造型价值、可本地清理、参考清楚且不依赖精确尺寸的组件才考虑 AI 3D。精确门、窗、栏杆和格栅至少需要正面与侧面/45 度可用参考。推荐路线与选中路线必须一致。`ai_3d` 是执行类别，实际提供方在提交前按当前工具、成本、授权和接口选择，不预设某一厂商。

AI 路线还要先写 `triangle_budget` 和 `low_poly_strategy`。生成质量档位不是面数参数；无法从实际接口确认面数上限时，生成后必须在 Blender 中减面或重拓扑，并保持轮廓、UV 接缝和材质边界。详细决策矩阵见 [generation-routing.md](generation-routing.md)。

生成器只支持一张图时：

1. 首选单件概念图；它同时保留轮廓、细节和材质。
2. 需要准确接口时可改用中性正面轮廓，再用文字补充风格。
3. 只上传风格锚会把几何带偏，需同时接受后期比例修正成本。

生成器支持多图时：

1. 支持“几何/风格”独立槽位时，几何槽放正面轮廓，风格槽放单件概念图。
2. 支持同一对象多视角时，只放中性正面和侧面；需要时再补背面。
3. 不把风格局部当作结构侧视图。
4. 第一件通过后把它的材质和风格设置作为后续风格锚。

不要把整栋 3/4 精修图混入多视图目录。多视图生成器会把它们当作同一对象的多个视角。

## 生成后检查

生成完成后，先做 Blender 网格、接口、材质节点和贴图映射静态审计，再渲染与参考模型派生视图同角度的正面、侧面和 3/4，制作并实际查看对照图。成品至少与两个模型派生裁剪比较，再用原始图检查材质、纹理和模型未可靠表达的微小细节。整栋远景不能代替单件近景。聊天中是否逐张展示不改变渲染门禁。

| 项目 | 通过标准 |
|---|---|
| 单体性 | 只有一个目标构件，没有粘上楼体、地面或相邻部件 |
| 背景 | 中性或透明，没有环境和人物 |
| 轮廓对照 | 大轮廓、顶部、底部和左右侧缘与参考图一致，没有缺角或多余体块 |
| 本体完整性 | 没有破洞、黑色背面、悬浮碎片、穿插或未封口的关键表面 |
| 接口 | 正侧主要连接面可辨认，能与锁定接口对齐 |
| 风格与材质 | 设计语言与参考图一致；墙面、木、石、瓦、玻璃没有明显的塑料感、拉伸纹理或色温漂移 |
| 结构 | 能解释其建造方式，没有诡异穿透和面条状结构 |
| 面片与表面 | 目标视角下没有明显折面、三角化、法线断裂、重合面、Z-fighting、黑缝和孤立碎片 |
| 构造逻辑 | 安装面、支撑、收口和与被连接件的关系能够解释，不是孤立悬浮件 |
| 可编辑性 | 主要轮廓可缩放，必要时能局部修整 |

差异必须写入 `qa.differences`。发现问题时先执行本地修复、重新静态审计并重渲染对照。只有主体结构无法挽救才申请付费重生成。

几何通过后还要赋最终材质与贴图并检查 Poly Haven 是否有匹配素材。材质审查必须包含至少两个渲染视图、参考对照、`polyhaven_checked=true`、基色/粗糙度/纹理尺度和投影检查，写入 `qa.material_review`。每次生成都必须运行 `blender_audit.py`，确认 `texture_mapping_audit` 没有 `FLAT + Object/Generated` 造成的跨立面拉伸风险。详见 [material-texture-validation.md](material-texture-validation.md)。

入口门头、雨棚和 porch 不能仅凭名称或单张图假定屋顶形式。先从模型派生视图确认构件是窄幅门头、贯通台阶的雨棚、上层阳台底面还是其他组合，再用局部网格法线检查坡面方向：正负对称的横向坡度通常表示双坡，单向进深坡度表示单坡，纯水平面表示平挑檐。支撑柱、墙装托架、宽度、出挑和檐口高度必须同时解释；参考中没有的落地高柱不得自行添加。有效参考里可见的檐柱、柱础、柱帽、柱顶横梁、随坡屋面托木、封檐板、托架和山墙三角窗属于同一门头的首次边界清单，必须一起参数化、建模并检查连接。不要把这些附属结构留到用户逐项提醒后再补。

## Blender 落位

1. 按包围盒修正比例。
2. 焊接共位顶点，删除零面积面、孤立碎片和错误背面，修补关键缺口并重算法线。
3. 对照参考图补回明确缺失的檐口、压边、门框、窗框和支撑结构。
4. 以锁定原点、朝向和接触面对齐。
5. 检查接口平整度，并生成修复前后的单件对照图。
6. 统一项目材质规则；先解决色差、粗糙度、法线和 UV 拉伸，再做整栋装配。
7. 通过实例复用进入整栋装配，并再次处理墙、屋面和门窗洞的缝合。
8. 重复组件不再次调用生成工具。
9. 组件通过 QA 后询问用户是否加入模型库；用户确认后才执行 `library-add`。

整栋装配后还要做构造逻辑分析：屋檐是否接墙和门廊、老虎窗是否嵌入屋面、凸窗/塔楼是否有支撑、檐沟是否接屋面、门窗是否有真实洞口、装饰件是否有安装面。发现松脱、悬空或断开时必须自行修补，并在获批验证批次中重新渲染，不能只记录问题后交给用户验收。

详细积分和修复规则见 [cost-and-repair.md](cost-and-repair.md)。

模型库的分类、检索、入库和复用规则见 [model-library.md](model-library.md)。
