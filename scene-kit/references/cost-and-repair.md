# 质量优先、参考一致与生成后修复

目标是先把最终效果、面片和构造逻辑修到可信，再优化生产时间与额度。积分应主要购买“造型创意和纹理生成价值”；省额度可以避免无意义重试，但不能成为接受明显可见缺陷的理由。

## 质量优先级

先满足尺寸、接口、可构建和交付平台预算等硬约束。在硬约束内按以下顺序取舍：

1. 目标视角效果匹配、轮廓和表面质量。
2. 面片、法线、材质、灯光和装配接缝。
3. 构造逻辑、支撑、收口和可建造性。
4. 其他生产效率优化。
5. 生产渲染时间和 token 消耗。

第 5 项只记录，不作为提前通过 `blocker/high` 可见缺陷的依据。需要新的付费生成时仍先告知用户并取得确认。

## 参考图优先

只要已经有该构件的单件概念图、清晰局部裁剪或可用的正侧轮廓，就先走图生 3D 或多视图生成：

1. 单件概念图是首要输入，它同时提供轮廓、细节和材质信息。
2. 支持独立槽位时，几何槽放中性轮廓，风格槽放单件概念图；两者角色必须标清。
3. 只有几何轮廓而没有风格图时，才用轮廓加文字补充材质和装饰语言。
4. 支持多视图时，只上传同一构件的正面、侧面和必要的背面，不把风格图冒充结构视角。
5. 纯文字生成是最后方案。参考图存在时，不先提交纯文字候选；若只能文字生成，应向用户说明平台限制和额外失败风险。

文字提示词是随同图片提交的控制信息，不是另一次付费生成的替代品。已经有能够表达设计目标的参考图时，不再先花一次额度生成普通文生图或纯文字 3D 候选。

## 拆件图片与多视图回查

拆件图片不能只看“看起来像”。每个拆件至少回到选中方向的两个原始多视图来源，确认构件完整、轮廓一致、安装面和侧厚没有丢失、没有把相邻构件或环境带进来。来源写入 `reference_pack.audit.source_views`，并与 `decomposition_audit` 保持一致。

如果单视图裁剪与其他视图对不上，先在 REFERENCES 修裁剪或重新选择来源；不要把这个矛盾带进 AI 3D 后靠重试猜。拆件后出现悬空、双面、墙体缺口或构件无法连续装配，也属于拆件设计问题，应先改拆件，不应把所有问题留给最终装配。

## 两条并列生成路径

生成阶段一开始就向用户说明以下两条路径，而不是只要求配置 API Key：

1. **Blender MCP 生成器**：启用 Hunyuan3D、Hyper3D、Tripo 或 Meshy，选择与账号一致的区域或 Domain，配置对应 API Key，完成只读鉴权检查后再提交。
2. **外部平台回传**：用户在自己的图生 3D 平台生成，再把 GLB/GLTF（优先）、OBJ 或 FBX 放入项目 `raw/`，或提供本地路径。助手负责导入、单体性检查、归一化和 QA。

外部回传说明必须写清每张图的角色。只有单图槽位时，优先单件几何轮廓并用文字补充风格；同时有几何和风格槽位时分别放入。多视图平台不能把风格局部冒充正侧视图；若平台强制把所有图片当成多视角，只上传同一构件的正面和侧面。

输出只允许目标单体，不含完整建筑、环境、地面、人物、文字或水印。保留纹理，使用构件 ID 命名。外部结果不降低比例、原点、朝向、接口、法线、UV、材质槽和视觉对照要求。

## 区域与 API 端点

正式生成前必须分别核对：

- 账号属于哪个区域或平台版本。
- 插件中的区域、Domain、Profile 或 Endpoint 是否与账号一致。
- 插件真正请求的 API 根路径，而不是产品展示页、工作台或开发者门户域名。
- Key 是否来自同一区域、同一工作区和同一种 API 凭证类型。
- 端点连通性、只读鉴权状态和余额是否足以提交任务。

Tripo 中国区 API 根路径为 `https://openapi.tripo3d.com/v3`，国际区为 `https://openapi.tripo3d.ai/v3`。故障诊断只记录状态码、错误码和脱敏配置，不展示 Key。其他生成器也必须按各自的实际 API 根路径检查。失败至少区分插件未启用、Key 缺失或无效、区域与端点不匹配、网络不可达四类，并从未重复提交的准确断点继续。

## 其他低成本措施

- 先在参考包中完成裁剪、透明背景、比例和接口整理，避免把问题带进生成器后靠重试修复。
- 每个构件先做一个候选，确认轮廓、接口和材质方向后再继续；不做没有决策价值的多候选批量生成。
- 第一件通过验收后作为风格锚。后续同类构件复用它的材质语言、参考图和生成设置。
- 左右窗、重复窗和重复老虎窗使用镜像、变换或实例；不为重复位置再次付费。
- 标准墙、楼板、台阶、檐沟、基础和规则线脚使用参数化或资产复用。
- 生成前检查账号区域、插件区域、API 根地址、Key 有效性和余额；低成本鉴权失败时不提交正式任务。
- 生成后先校正比例、原点、朝向、法线和材质；能通过本地修复解决的，不重新生成。
- 用户只提出材质或接缝问题时，先修材质和接口；不要用新模型覆盖已经正确的轮廓。
- 只有轮廓缺失、主体结构错误或造型语言无法通过本地修面和调整挽救时，才申请有明确目标的付费重生成。先说明已尝试的修复、剩余缺陷和预期收益；重生成继续使用原参考图，不能重复同一个无效提示词。

## 生成后必须做视觉对照

导入 Blender 后，不能只看 `review` 布尔字段或只看整栋远景。必须把生成单体和原参考图放在同一审阅上下文中比较：

1. 用中性灯光分别渲染正面、侧面和 3/4 视图；参考图包含局部细节时，再渲染同角度近景。
2. 将这些视图与对应的 `geometry`、`appearance` 参考图并排或叠放，生成并保存对照图。
3. 先看大轮廓和接口，再看门窗洞、檐口、顶部、底部、侧缘和材质。
4. 至少检查缺失面、破洞、悬浮碎片、错误悬挑、穿插、黑色背面、拉伸纹理、塑料感和与参考图不符的色温。
5. 把差异写成可执行清单，不只写“差不多”或“检查通过”。

建议对照目录：

```text
preview/qa/<part_id>/
  reference.png
  front.png
  side.png
  three_quarter.png
  comparison.png
```

## 修复顺序

单件在进入装配前完成以下修复，整栋完成后必须重新检查缝合：

1. **比例和接口**：按 `locked` 数据归一化，修正原点、朝向、墙面和屋面接触。
2. **网格本体**：焊接共位顶点，删除零面积面、孤立碎片和错误背面，补齐缺失的封口，重算法线。
3. **语义修复**：补回参考图明确存在但生成缺失的檐口、顶部压边、窗框、门框或支撑结构。
4. **材质**：先修正基础色、粗糙度、法线强度、UV 拉伸和重复；再按设计合同统一墙、石、木、瓦和玻璃规则。
5. **装配缝合**：处理老虎窗嵌屋面、入口接墙、凸窗支撑、门窗洞和重复实例接缝。
6. **复审**：修复前后都保留对照图；确认修复没有破坏轮廓或接口后才通过。

缺失的关键结构不能只用一块无材质的挡片遮住。补件要延续原单体的轮廓、厚度和材质，并在记录中说明新增几何。

## 最终面片与智能构造精修

`ASSEMBLY` 完成后进入 `FINISHING`。这一阶段必须检查 AI、参数化、复用和模型库资产，不能只看 AI 单体。

面片与表面：

- 目标输出分辨率下没有明显三角化、低模折面、异常尖锐/过度平滑、法线断裂、明暗条纹；
- 没有重合面、Z-fighting、零面积面、翻转法线、悬浮碎片、布尔烂面、明显 UV 拉伸；
- 圆角、拱券、曲面、窗洞、檐口和屋面分段足够，关键硬边有合理支撑线；
- 墙、屋面、门窗、塔楼、老虎窗、栏杆和台阶的接缝没有黑缝、漏光或用挡片遮盖。

除了和参考图比较，还要做构造逻辑智能分析。把关键关系逐项记录在 `finishing.logical_relationships`：

- 屋檐/雨棚是否与墙体和门廊连续连接；
- 老虎窗是否真正嵌入屋面，山墙和檐口是否收口；
- 凸窗和塔楼是否有支撑、托座或与主体连续的结构；
- 门窗洞、台阶、花箱、壁灯和装饰件是否有合理的接触面；
- 檐沟、雨水管、屋脊和压边是否接在正确表面；
- 是否有拆件造成的孤立块、重复实体、缺失背面、无支撑悬挑或无法防水/受力的状态。

发现“屋檐和下面门廊松垮”这类问题时，应主动补墙体嵌入、梁端/托座、屋面延伸和收口，并重新渲染近景验证。不能仅记录为差异、等待用户指出，也不能用灯光或贴图掩盖。

每个最终问题写入 `finishing.issues`，包含 `severity`、`status`、`observation` 和 `disposition`。`blocker/high` 只能为 `fixed`；`medium/low` 可 `deferred`，但必须明确记录。`artifact.blend_sha256`、`artifact.revision` 和 `finishing.revision` 必须对应同一产物。

## 记录字段

每个 AI 单体至少记录：

```json
{
  "generation": {
    "input_mode": "image_to_3d",
    "references_used": ["preview/references/window_01/concept.png"],
    "candidate_count": 1,
    "paid_retries": 0
  },
  "qa": {
    "comparison_path": "preview/qa/window_01/comparison.png",
    "differences": [],
    "repairs": ["welded coincident vertices", "rebuilt missing top cap"],
    "result": "pass"
  }
}
```

`input_mode` 优先使用 `image_to_3d` 或 `multiview_to_3d`；纯文字生成必须说明为什么无法使用已存在的参考图。`differences` 为空也必须来自实际对照，而不是未查看图片。`result` 只有在单件修复并重新对照后才能设为 `pass`。
